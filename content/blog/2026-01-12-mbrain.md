Yesterday I watched a [YouTube video](https://www.youtube.com/watch?v=0TpON5T-Sw4) that changed how I think about note-taking. The creator talked about how our brains aren't designed for storing information. I think he's right.

Recalling information quickly is hard. So his idea was simple: stop trying to remember everything and use AI to retrieve it instead. He called this a "second brain."

I loved this idea so much that I built my own version in a day.

## How It Works

I use Slack as my interface because we already use it at work. I set up a private Slack workspace for myself and created a channel called mBrain (for "Malvik Brain").

When I write something like "Call my parents today," the note goes to a Slack app running on Vercel. I'm using the Claude SDK to classify the note. It gets a category like "relationships" or "family," and then it's stored in a Notion table.

The table uses the PARA system from the video: Projects, Areas, Resources, and Archives. I get feedback about where each note was stored, including a confidence level between 0 and 1. When the AI can't categorize something confidently, it goes into an "uncategorized" bucket.

I'm genuinely happy with this solution.

## What's Next

Over the next few weeks, I'm adding actions. When I want to create a GitHub issue for a project, it just does it. Same with creating an Outlook invitation. I'm building actual automation into my second brain.

## Why Not a Workflow Engine?

I mentioned this in my previous post, but I initially tried building this with AI workflow engines like n8n, OpenAI Agent Builder, Make, or Zapier. It sounds straightforward. It's just a workflow.

But it wasn't. Handling all the different scenarios became overwhelming. What happens if you don't get a reminder? How do you get feedback? Should reminders be weekly or daily? What are all the error scenarios? Every edge case needs explicit handling in a workflow engine.

## Claude Code Made This Easy

I'm using Vercel and developing with Claude Code. This is where it got interesting.

Claude Code has deep knowledge of technologies like Vercel, Notion, and Slack. Because of this, building the solution was surprisingly fast. I also added a custom skill based on NASA's coding rules. This skill runs as a pre-hook before any changes, so security and stability considerations are baked into every coding session.

I run these skills before commits too. Not every time, but often enough that I end up with a stable, well-thought-through solution.

The lesson: Sometimes you need to stop planning the perfect architecture and just build something. With the right tools, a day is enough to create something useful.
